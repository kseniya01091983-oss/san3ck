# Состояние проекта FastNotes

## Назначение

FastNotes сохраняет личные заметки, ссылки, рекомендации, изображения и файлы через Telegram и позволяет просматривать и искать их на сайте.

## Текущее устройство

- Исходная версия работает на Python и aiogram в режиме polling.
- Данные хранятся в локальной SQLite-базе `notes.db`.
- Локальный aiohttp-сервер обслуживает REST API, SSE и сайт `site/index.html`.
- AI-обработка поддерживает Groq, Gemini, OpenRouter и локальный резервный алгоритм.
- Реализованы создание, список, просмотр, редактирование, скрытие, публикация и удаление заметок.
- Сайт FastNotes имеет светлую, тёмную и автоматическую темы, поиск, фильтры и разделы.

## Целевая версия

- Telegram webhook и серверная логика: Cloudflare Worker на TypeScript.
- База заметок и метаданных: Cloudflare D1.
- Изображения и документы: описание и Telegram `file_id` в D1; R2 не используется.
- Обработка текста и изображений: OpenRouter.
- Извлечение содержимого ссылок: Tavily Extract.
- Смысловой индекс для RAG: Upstash Vector; D1 остаётся источником истины.
- Каталог фильмов и сериалов: TMDB Read API.
- Существующий сайт: Worker Static Assets и защищённый API.

## Основные файлы

- `main.py`, `bot/` — исходный Python-бот.
- `site/index.html` — интерфейс FastNotes.
- `notes.db` — исходная база и резервная копия.
- `worker/src/` — новая облачная реализация.
- `worker/migrations/` — схема D1 и полнотекстовый поиск.
- `worker/scripts/export_sqlite_to_d1.py` — безопасный экспорт SQLite в D1 SQL.
- `worker/test/` — модульные и интеграционные тесты Worker.

## Важные решения

- У сервиса два разрешённых пользователя: владелец и преподаватель. Каждый видит и изменяет только свои записи благодаря фильтрации по `owner_telegram_id`.
- Внешний вид FastNotes сохраняется.
- Python-версия остаётся в репозитории как исходная работа Саши.
- Сайт получает временную ссылку из Telegram и защищённую cookie-сессию.
- По выбору владельца сайт не выполняет фоновые обновления: одна загрузка при открытии, затем только кнопка `Обновить`.
- Панель разделов всегда видна при новом открытии сайта на компьютере; её временное скрытие не сохраняется после перезагрузки.
- Одна модель текста и изображений: `z-ai/glm-5.3-flash`. Разрешены только DeepInfra, Novita, Z.AI и GMICloud; затем отдельный резерв DeepSeek и бесплатный маршрут.
- От R2 отказались по просьбе владельца: D1 хранит Telegram `file_id`, а Worker временно получает файл из Telegram для анализа или защищённой выдачи сайту.
- AI-обогащение не должно блокировать доступ к исходной записи: заметка публикуется сразу, а внешние запросы имеют ограниченное время ожидания.
- Telegram не выполняет автоматические повторы: новый AI-запрос запускается только новым сообщением пользователя или кнопкой `Повторить`.
- Меню команд Telegram регистрируется только после `/start`; поиск и подсчёт результатов сайта выполняются локально в браузере.
- D1 всегда проверяет результаты Upstash и остаётся источником истины; недоступность Upstash не мешает обычному FTS5-поиску.
- В актуальном интерфейсе Upstash вместо ранее запланированной BGE-M3 выбрана доступная встроенная пара: Dense `openai/text-embedding-3-small` и Sparse `BM25`. Код менять не требуется, потому что обе модели поддерживают используемые текстовые REST-команды `upsert-data` и `query-data`; `Custom` не используется.
- Вектор обновляется только при изменении заголовка, описания или тегов готовой опубликованной заметки.
- TMDB-карточка никогда не сохраняется без явного подтверждения пользователя.

## Известные ограничения

- Полный пользовательский сквозной сценарий с сообщениями из приложения Telegram рекомендуется дополнительно пройти вручную.
- Уже открытая страница не увидит новую Telegram-заметку, пока пользователь не нажмёт `Обновить` или не откроет сайт заново. Это сознательный выбор ради минимального расхода лимитов.
- Очищенная ветка `cloudflare-migration` опубликована в `kseniya01091983-oss/san3ck`. Её Git-история не содержит `notes.db`.
- Ключи уже сохранены в Cloudflare Secrets и не находятся в проекте или GitHub.
- Автоматическая интеграционная проверка внешних сервисов уже проходила успешно; ручная проверка интерфейса Telegram после последнего обновления остаётся рекомендуемой.
- Upstash и TMDB ещё не подключены в рабочем Cloudflare, поэтому настоящие внешние сценарии второй части пока не выполнялись.

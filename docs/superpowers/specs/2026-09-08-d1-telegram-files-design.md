# FastNotes без R2: схема хранения и маршрутизация моделей

## Цель

Сохранить существующую облачную версию FastNotes и убрать обязательный Cloudflare R2. Заметки и метаданные остаются в D1. Для изображений и документов сохраняются постоянные идентификаторы Telegram, поэтому исходный файл можно повторно получить через Telegram Bot API.

## Хранение вложений

- Таблица `attachments` хранит `telegram_file_id`, `telegram_file_unique_id`, имя, MIME-тип, размер и размеры изображения.
- Байты изображений и документов не записываются ни в D1, ни в репозиторий.
- При первом получении изображения Worker временно скачивает его из Telegram, передаёт модели для описания и сразу освобождает память.
- Защищённый маршрут сайта `/api/files/:id` проверяет сессию, получает актуальный `file_path` по сохранённому `file_id` и передаёт файл из Telegram пользователю.
- Если Telegram больше не может выдать файл, заметка и её описание всё равно сохраняются; интерфейс показывает ошибку только для самого вложения.

## OpenRouter

Основная мультимодальная модель для текста и изображений — `z-ai/glm-5.3-flash`.

Запросы к GLM ограничены следующими провайдерами и их порядком:

1. `deepinfra`;
2. `novita`;
3. `z-ai`;
4. `gmicloud`.

Если все четыре маршрута GLM недоступны, Worker выполняет отдельную попытку через `deepseek/deepseek-v4-flash-0731` с автоматическим выбором провайдера. Для изображения этот текстовый резерв пропускается. Последняя попытка — `openrouter/free`; OpenRouter сам подбирает бесплатную модель с нужными возможностями запроса.

Такое разделение важно: ограничения по провайдерам GLM не должны случайно ограничить резервные модели.

## Миграция базы

- Существующая миграция `0001_initial.sql` не меняется: это сохраняет историю уже созданных D1-баз.
- Новая миграция пересоздаёт только таблицу `attachments` без поля `r2_key`, сохраняя существующие метаданные.
- `notes.db` читается экспортирующим скриптом без изменений. Временный SQL хранится только в игнорируемой папке `worker/.data/`.

## Ошибки и повторная обработка

- Сначала создаётся заметка и сохраняется Telegram `file_id`, затем запускается AI-анализ.
- При сбое модельного API запись получает статус `failed`, но исходная подпись, `file_id` и метаданные остаются в D1.
- Кнопка повтора заново получает изображение из Telegram по `file_id` и повторяет описание.

# Доступ преподавателя с отдельными заметками

## Цель

Разрешить Telegram-пользователю `126041348` полноценно проверять FastNotes, не открывая ему заметки владельца и не позволяя изменять или удалять их.

## Выбранное решение

- `OWNER_TELEGRAM_ID` остаётся главным владельцем и продолжает видеть прежние заметки.
- В Worker добавляется обычная переменная `TEACHER_TELEGRAM_ID` со значением `126041348`. Telegram ID не является ключом API и может храниться в конфигурации.
- Доступ разрешается только двум ID: владельцу и преподавателю. Все остальные по-прежнему получают сообщение `Доступ закрыт`.
- Для каждой разрешённой операции идентификатор пользователя Telegram становится идентификатором пространства данных. Поэтому преподаватель использует те же команды и функции, но запросы D1 всегда фильтруются по `126041348`.
- Существующие заметки владельца, их ID, вложения и исходная `notes.db` не изменяются.

## Telegram

После проверки разрешённого ID Worker передаёт ID действующего пользователя во все операции с заметками, вложениями, поиском и состоянием редактирования. Преподаватель сможет создавать текст, ссылки, изображения и файлы, пользоваться `/notes`, `/ask`, `/site`, редактированием, скрытием и удалением только в своём пространстве.

Повтор Telegram update по-прежнему отсекается общей таблицей `telegram_updates`: Telegram `update_id` уникален для бота и не требует разделения по пользователям.

## Сайт

Команда `/site` создаёт подписанную ссылку для того пользователя, который вызвал команду. Подписанный токен и cookie-сессия содержат его Telegram ID. Worker проверяет подпись, срок и наличие ID в списке разрешённых пользователей, после чего API сайта использует этот ID во всех запросах D1.

Таким образом, ссылка владельца открывает заметки владельца, а ссылка преподавателя — только тестовые заметки преподавателя. Передавать ссылки друг другу не следует: действующая ссылка или cookie дают доступ к соответствующему пространству до истечения срока.

## Изменения кода

- Добавить небольшой модуль доступа: чтение и проверка `OWNER_TELEGRAM_ID` и `TEACHER_TELEGRAM_ID`.
- Передавать действующий Telegram ID из webhook в обработчики Telegram вместо постоянного использования ID владельца.
- Возвращать ID сессии из проверки cookie и передавать его в API сайта.
- Обновить тип `Env`, `wrangler.jsonc`, русскую документацию и тестовое окружение.
- Схема D1 не меняется: поле `owner_telegram_id` уже обеспечивает нужное разделение.

## Ошибки и безопасное поведение

- Некорректный ID владельца считается ошибкой конфигурации.
- Некорректный дополнительный ID игнорируется; доступ владельца сохраняется.
- ID, отсутствующий в списке, не получает ссылку на сайт и не запускает OpenRouter или Tavily.
- Все чтения, изменения, удаления и выдача вложений требуют совпадения `owner_telegram_id` с ID действующей Telegram- или сайт-сессии.

## Проверка

- Владелец продолжает видеть старые заметки.
- `126041348` получает ответ на `/start` и может выполнить полный CRUD.
- Заметка преподавателя не видна владельцу, и наоборот.
- `/ask` использует только записи действующего пользователя.
- Ссылки `/site` владельца и преподавателя открывают разные наборы данных.
- Посторонний ID получает `Доступ закрыт` и не вызывает AI.
- Повтор одного Telegram update не создаёт дубль.

## Развёртывание

После успешных тестов Worker развёртывается в существующий сервис, webhook менять не требуется. Новых секретов и действий в кабинетах Cloudflare, Telegram, OpenRouter или Tavily не требуется.
